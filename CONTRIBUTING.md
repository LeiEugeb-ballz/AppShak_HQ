# AppShak HQ — Contributing Guide

---

Begin with [CURRENT_STATUS.md](CURRENT_STATUS.md) and the
[Documentation Index](docs/INDEX.md). This guide retains the contribution
controls established for Phase 3B certification work.

## Before You Write a Single Line

1. Read `ONBOARDING.md` — the architecture, the phase, the hard rules.
2. Know which phase you are working on. If unsure, ask.
3. Confirm the task you're working on exists in the current phase checklist.
4. Do not start work on any phase above the current active one.

---

## Phase Lock

This lock records the controls for Phase 3B certification work. It does not
replace the repository-wide status record in
[CURRENT_STATUS.md](CURRENT_STATUS.md).

**Current active phase: 3B — Certification**

Work permitted in Phase 3B:
- Fixing crashes or hangs in the swarm/supervisor
- Fixing null fields in the projection view
- Fixing broken integrity/inspection report generation
- Fixing replay determinism failures
- Running and interpreting the certification harness

Work NOT permitted until 3B is signed off:
- Any Phase 4+ code (retry loops, failure refinement, boardroom decision system)
- Any new agent capabilities
- Any UI enhancements beyond what's needed to verify the run
- Any governance layer changes

---

## Branch Strategy

| Branch | Purpose |
|--------|---------|
| `main` | Clean, phase-complete state. Only merge after evidence bundle passes. |
| `phase-3b/<your-name>` | Your working branch for Phase 3B fixes |

Never commit directly to `main`.

---

## Commit Message Format

```
[3B] Short description of what was fixed

- What was broken
- What you changed
- What test proves it works now
```

Example:
```
[3B] Fix null state field in projection for idle workers

- Workers in IDLE state were not emitting last_event_type
- Added fallback in projector to default to "HEARTBEAT" for idle workers
- Chamber B and unit test test_projection_idle now pass
```

## Before Submitting a PR

- [ ] All chambers pass (`chamber_a`, `chamber_b`, `chamber_c`)
- [ ] All unit tests pass
- [ ] `CERTIFICATION_HARNESS.py --quick` passes (5-minute smoke test)
- [ ] No new files added outside your scope
- [ ] No `appshak_state/` files committed (these are runtime, not source)
- [ ] No commented-out code left in
- [ ] No `print()` debug statements left in

---

## Things That Will Get Your PR Rejected

- Any Phase 4+ code in a Phase 3B PR
- Changes to `appshak_governance/` without explicit approval
- Changes to the Prime Directive or constitutional constants
- Any commit that breaks a passing chamber
- Committing `appshak_state/` runtime files
- Bypassing the event bus (direct agent-to-agent calls)
- Any external action not gated through ChiefAgent

## Running the Tests

```bash
# Quick environment check
python -m appshak_substrate.chambers.chamber_a_durability
python -m appshak_substrate.chambers.chamber_b_isolation
python -m appshak_substrate.chambers.chamber_c_tool_enforcement

# Full unit tests
python -m unittest discover -s tests -p "test_*.py" -v

# Governance tests specifically
python -m unittest tests.test_governance_layer -v

# Quick certification smoke test (5 min)
python CERTIFICATION_HARNESS.py --quick

# Full 6-hour certification (only when ready)
python CERTIFICATION_HARNESS.py
```

## State Files

The `appshak_state/` directory is **runtime only**. It is in `.gitignore`. Do not commit it.

If you need to share a run's output, use the `certification_evidence/` bundle generated by the harness.

## The Constitution Comes First

This project has a governing constitution. It is not decorative. When there is a conflict between "what seems faster" and "what the constitution says," the constitution wins. Always.

The permanent North Star:
> *"This organisation exists to continuously identify valuable problems, build solutions, and increase its own capability and autonomy over time."*

Every architectural decision traces back to this.
