# AppShak HQ

AppShak is a governed, event-driven multi-agent runtime. It provides a durable
SQLite-backed substrate for worker processes, materializes a read-only
projection of their state, and exposes that state through observability,
integrity, stability, inspection, and governance layers.

The project exists to make multi-agent operation observable, deterministic
where required, and auditable through durable events, replayable governance
records, and certification evidence. It is not a generic chatbot framework or
a feature demo.

## Repository map

| Area | Role |
|---|---|
| `appshak/` | Core kernel, agents, event bus, memory, safeguards, and plugin runtime. |
| `appshak_substrate/` | Durable mail store, worker supervision, worktree isolation, policy, and validation chambers. |
| `appshak_projection/` | Event-to-state materialization. |
| `appshak_observability/` | FastAPI read-only observability backend and WebSocket streams. |
| `appshak-ui/` | Vite/React observability UI. |
| `appshak_governance/` | Deterministic registry, trust, arbitration, ledger, and replay logic. |
| `appshak_integrity/`, `appshak_stability/`, `appshak_inspection/` | Integrity reports, stability runs, and inspection timelines. |
| `appshak_phase4/` | Phase 4 orchestration, evaluation, writers, and runtime components. |
| `tests/` | Python unit and integration suites. |
| `docs/` | Canonical documentation, phase records, plans, and evidence. |
| `run_archives/`, `stashed_instances_2026-02-19/`, `untraacked_20260503/` | Preserved certification, implementation, and generated-evidence history; not primary runtime source. |

`appshak_state/` and `workspaces/` are runtime locations. They are generated by
normal commands and are intentionally not the canonical source of history.

## Run a quick verification

From the repository root, after environment setup:

```bash
python -m appshak_substrate.chambers.chamber_a_durability
python -m appshak_substrate.chambers.chamber_b_isolation
python -m appshak_substrate.chambers.chamber_c_tool_enforcement
python -m unittest discover -s tests -p "test_*.py" -v
```

For the full certification sequence, see [CERTIFICATION_HARNESS.py](CERTIFICATION_HARNESS.py)
and the [Certification Planning Pack](docs/certification/README.md).

## Run and observe the stack

The following starts the principal services. Use separate terminals after the
environment and state directories have been prepared.

```bash
# Terminal A: durable swarm
python -m appshak_substrate.run_swarm --agents recon forge command --durable --worktrees --duration-seconds 1200

# Terminal B: projection materializer
python -m appshak_projection.run_projector --mailstore-db appshak_state/substrate/mailstore.db --view-path appshak_state/projection/view.json --poll-interval 1

# Terminal C: observability API and WebSocket backend
python -m appshak_observability.server --host 127.0.0.1 --port 8010 --projection-view appshak_state/projection/view.json

# Terminal D: UI
cd appshak-ui
npm install
npm run dev
```

Open `http://127.0.0.1:5173`. The UI reads the backend snapshot endpoint and
WebSocket stream. Additional integrity, inspection, and stability commands are
in [docs/INDEX.md](docs/INDEX.md#active-runtime-and-subsystem-documents).
